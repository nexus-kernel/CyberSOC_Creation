# CyberSOC Monthly Report Toolkit v1.4.0

`Export-CyberSocToolkit.ps1` writes this file into each release zip with the packaging date.

## Prerequisites

- PowerShell 7.x (Windows PowerShell 5.1 also works).
- Azure CLI 2.50 or later (`brew install azure-cli` or `winget install Microsoft.AzureCLI`).
- Node.js 18 or later, for the PowerPoint editions. Without it the HTML report is still written.
- The ExchangeOnlineManagement module, installed for the current user on the first run unless you pass `-SkipExchange`.

For a git checkout, run `npm ci` using the committed lockfile before generating
PowerPoint files. Release bundles may include node_modules. Developer tests and
cloud environment setup are documented in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md);
reviewed CI and bootstrap are documented in [.github/REVIEW_GATE.md](.github/REVIEW_GATE.md).

## Windows

Files extracted from a downloaded zip are marked as coming from the internet, and PowerShell blocks them under the RemoteSigned policy. Run this once from the extracted folder:

```powershell
Get-ChildItem -Recurse -File | Unblock-File
```

## Check the install

This writes the controls standard as HTML and PPTX without signing in anywhere. Both files appearing means the report assets, Node.js and pptxgenjs all work.

```powershell
pwsh ./New-CyberSocControlsStandard.ps1 -OutputPath ./install-check/standard.html
```

## Collect evidence

```powershell
pwsh ./Get-CyberSocEvidence.ps1 -TenantId <tenant> -SubscriptionId <subscription> -ReportMonth <yyyy-MM> -VulnAssessmentPath <vulnerability assessment run folders>
```

The window is the report month and the two full months before it, the 90-day trend. The report month defaults to the last full month. `-VulnAssessmentPath` imports the monthly Atmosera.VulnAssessment runs of that window for these subscriptions. A pack collected without them takes them later with `Import-CyberSocVulnAssessment.ps1 -EvidencePath <pack> -VulnAssessmentPath <runs>`, then `New-CyberSocReport.ps1 -EvidencePath <pack>`.

Each run writes an evidence pack with the report in two HTML editions and a deck, and the SecOps worklist (`04-secops-worklist.md` and `.csv`). Send the client `03-security-report.client.html` and `03-security-report.pptx`. `03-security-report.html` is the internal edition, with the presenter notes, the evidence review, the collection register and the subscription and workspace IDs, so it never goes to the client. The client edition and the deck need Node.js. The worklist names client resources and is internal only, so it never goes to the client either. Get-CyberSocEvidence.README.md covers parameters, permissions and sign-ins.

## Raise the hardening change requests

```powershell
pwsh ./New-CyberSocChangeRequests.ps1 -EvidencePath <pack>
```

Writes `05-change-requests` into the pack: one change request for each low-impact hardening item that still has resources to fix, and a ready-to-send client email for the changes that need the client first. New-CyberSocChangeRequests.README.md covers the changes and the options.

## Integrity

In a release zip, MANIFEST.sha256 holds the SHA-256 of every other file in the folder. The copy in the repository root is from the EBR 1.14.0 release this repository was copied from, and is regenerated by the next packaging. On macOS or Linux, check it with `shasum -a 256 -c MANIFEST.sha256`.
